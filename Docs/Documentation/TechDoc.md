# 기술 문서 규칙 / 양식

> 기능별 기술 문서를 작성·검수할 때 읽는다.

---

## 1. 공통

- 위치 : `Docs/Tech/[기능명].md`. 기능명은 PascalCase 영어. (예 : `Docs/Tech/PlayerMovement.md`)
- 현재 구현된 코드만 서술한다. 계획·미구현 기능은 적지 않는다.
- 모든 서술의 근거는 실제 소스코드다. 브리핑이나 보고가 코드와 다르면 임의로 맞추지 않고 사용자에게 확인받는다.
- 기존 문서를 갱신할 때는 이번 작업으로 달라진 부분만 고친다.
- 클래스·메서드·필드·에셋 이름은 백틱으로 감싸고 코드와 똑같이 적는다. (코드가 컨벤션과 달라도 코드를 따른다)
- 파일 경로는 `Assets/`부터 적는다.
- `미검증` 등급인 내용은 끝에 `(미검증)`을 붙인다.

## 2. 섹션별 규칙

| 섹션 | 규칙 |
|---|---|
| 개요 | 기능이 하는 일 1~3줄, 연결 Issue 번호 (없으면 "없음") |
| 구성 파일 | 스크립트, 프리팹, 에셋의 경로와 역할 |
| 주요 요소 | 클래스별 public 메서드와 Inspector 노출 필드. private은 동작 이해에 꼭 필요할 때만 |
| 동작 흐름 | 입력(또는 시작 시점)부터 결과까지 번호 목록, 단계마다 담당 클래스 / 메서드 |
| 에디터 설정 | 씬 / 프리팹에서 연결할 항목과 방법. 항목마다 `(미검증)`. 없으면 "없음" |
| 변경 이력 | 생성 / 갱신마다 한 줄 추가 |
