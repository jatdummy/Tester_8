# Unity MCP 사용 규칙

> `Docs/TechSpec.md`의 `Unity MCP`가 `켬`일 때만 읽고 따른다. `끔`이면 Unity MCP를 사용하지 않는다.

---

## 1. 연결 정보

| 항목 | 값 | 설명 |
|---|---|---|
| MCP 서버 이름 | | `/mcp`에 표시되는 서버 이름 |
| 조회 도구 | | `도구 이름 (허용 action)`을 쉼표로 구분. 예: `mcp__<서버>__read_console (get)` |
| 새로고침 도구 | | 선택. Unity에 새로고침 / 컴파일을 요청하는 도구. 메인만 사용한다. |

## 2. 조회

- 조회는 Unity 상태를 바꾸지 않는 호출이며, 위 `조회 도구`에 적힌 도구와 action만 쓴다.
- 한 도구에 조회와 변경 action이 섞여 있으면 조회 action만 호출한다.
- 메인과 서브에이전트 모두 쓸 수 있다. 서브에이전트는 자기 `tools`에 있는 조회 도구만 쓴다.
- 조회로 확인할 수 있는 항목 : 콘솔 Error / Warning 로그, 씬 / 프리팹의 컴포넌트와 참조 연결.
- 조회로 확인할 수 있는 항목은 Issue DoD에 `(사용자 확인)`을 붙이지 않는다.

## 3. 검증 등급

- 아래를 모두 확인했을 때만 조회 결과가 `검증`이다. 하나라도 안 되거나 도구를 쓸 수 없으면 `미검증`이다.
  1. 마지막 스크립트 변경 뒤 Unity가 다시 컴파일했다. (메인이 새로고침 도구를 실행하거나, 사용자에게 Unity 에디터를 한 번 선택해 달라고 요청한다)
  2. 에디터가 컴파일 중이 아니다.
  3. 그 시점 이후의 콘솔 로그나 상태를 조회했다.
- reviewer 호출 전에 새로고침 도구가 있으면 메인이 실행한다.
- PR 체크와 DoD 판정에 쓰는 콘솔 결과는 PR 생성 직전에 메인이 다시 조회한 결과만 쓴다.

## 4. 변경

- 씬, 프리팹, 에셋, 에디터 설정을 바꾸는 호출은 아래를 모두 만족할 때 메인만 한다. 서브에이전트는 하지 않는다.
  1. 승인된 브리핑의 `파일`에 대상 경로가 있다. (에디터 설정이면 `ProjectSettings/*.asset`)
  2. 실행 직전에 대상과 내용을 보여 주고 확인받았다.
- 브리핑의 작업 순서에 `(메인, MCP 변경)`으로 표시한다. developer, reviewer는 이 단계를 미이행으로 보지 않는다.
- 시점은 reviewer `통과` 뒤다. 바꾼 직후 다시 조회하고, 대상·내용·조회 결과·등급을 검수 요청에 넣는다.
- MCP로 하지 않는 것 : C# 파일 생성·수정·삭제, 임의 코드 실행, 메뉴 실행, 여러 호출을 묶어 실행하는 도구.
- Play 모드 진입과 테스트 실행은 변경으로 보고, 확인받은 뒤 메인만 한다.
