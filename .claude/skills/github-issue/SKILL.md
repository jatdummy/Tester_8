# Github Issue 등록

> Label은 `CLAUDE.md` `5. Label · 말머리 · 브랜치` 표를 쓴다.
> 등록이 실패하면 `gh auth status`, `git remote -v`부터 확인을 안내한다.

## 1. 권유

사용자가 직접 요청했으면 생략한다.

```markdown
**Issue 등록 권유** : [권유 사유]

- 제안 제목 : [기능 단위 제목]
- 범위 : [한 줄 요약]

이슈로 등록할까요?
```

## 2. 정보 수집

- 배경 / 목적을 사용자에게 묻는다. 답이 없거나 생략하라고 하면 Claude가 추정해 쓰고, 3단계 승인 요청에 `(추정)`으로 표시한다.
- 나머지 섹션은 아래 규칙으로 Claude가 초안을 쓴다. 코드·문서는 읽기만 한다.

```markdown
**Issue 작성 정보 요청** : [제안 제목]

- 이 작업이 필요한 배경 / 목적을 알려주세요.
  - (예) [추정한 배경 1줄]
```

## 3. 작성 규칙

| 섹션 | 규칙 |
|---|---|
| 제목 | 20자 이내, 기능 단위 (예 : `플레이어 이동 구현`) |
| 배경 / 목적 | 간결한 리스트 |
| 목표 (To-be) | 완료 시 예상 동작·결과, 간결한 리스트 |
| 작업 내용 | 파일 경로별 생성 / 수정 / 삭제 (예 : `` `Assets/Scripts/Core/DamageInfo.cs` 생성 ``) |
| 완료조건 (DoD) | 목표·작업 내용과 에디터 에러 여부를 체크리스트로. 사용자만 확인할 수 있는 항목(실행 결과, 에디터 콘솔)은 끝에 `(사용자 확인)` |
| 특이사항 | 선행 조건, 연관 Issue(`#번호` 태그), 해소된 블로커가 있을 때만. 없으면 섹션 삭제 |

양식 (제목은 `--title`로 넣는다) :

```markdown
## 배경 / 목적
- 

## 목표 (To-be)
- 

## 작업 내용
- 

## 완료조건 (DoD)
- [ ] 
- [ ] 유니티 에디터에서 컴파일 에러 및 Error, Warning 로그가 발생하지 않는다. (사용자 확인)

## 특이사항
- 
```

## 4. 등록 전 승인

요약만 보여 주고, "전문" 요청 시 본문 전체를 보여 준다. 승인 없이 등록하지 않는다.

```markdown
**Issue 등록 확인**

| 항목 | 내용 |
|---|---|
| 제목 | |
| Label | |
| 목표 | [1~2줄] |
| 작업 파일 | [생성 n / 수정 n / 삭제 n] |
| DoD | [n개 (사용자 확인 n개)] |
| 특이사항 | [요약 / 없음] |

등록할까요? (전문 확인 시 "전문")
```

## 5. 등록

- `gh issue create --title "<제목>" --label "<Label>" --body-file -` (본문은 표준 입력). Label이 저장소에 없으면 `gh label create`로 먼저 만든다.
- 일반 등록 완료 :

```markdown
**Issue 등록 완료** : #[번호] [제목]

- 링크 : [URL]
- 제안 브랜치 : `[접두사]/[번호]-[작업명]`

브랜치를 만든 뒤 착수명령을 주시면 브리핑을 진행합니다.
```

- 작업 도중 등록(범위 밖 발견) :

```markdown
**Issue 등록 완료** : #[번호] [제목]

- 링크 : [URL]

현재 작업을 이어갑니다. 이 Issue는 현재 작업을 마친 뒤 별도 브랜치에서 착수해 주세요.
```
